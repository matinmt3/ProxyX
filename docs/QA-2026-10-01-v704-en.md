## Fixes

- Scenario comparison uses live Room observations instead of stale selected objects. Deleted routes disappear from comparison; the newest usable public transfer or private route test is selected.
- Capacity and scenario scores reject incomplete/stale native transfers, offline or hard-failed routes, and evidence measured on another network. Direct baseline UI clears when the current network/baseline disappears.
- Private tests reserve the network measurement slot and always release it, including missing-node/storage failures. Manual route, native, private, collection and baseline actions respect the current unmetered-only setting.
- Fresh collection clears search, status, sort, selection, comparison and completed benchmark state. The old benchmark recovery journal is removed atomically with the first successful database replacement. Failed/empty collection still preserves the existing usable snapshot.
- Returning Home makes active advanced filters visible. Narrow mobile filter labels fit; the Telegram connection action has a fixed-size icon and accessible name/tooltip.
- Source success totals refer to successful latest recorded fetches from enabled catalog sources, not historic successes from removed or currently failed sources.
- Small benchmark queues include genuinely MTProto-responsive prior routes first, then untested/old routes. Every selected route undergoes new measurements; no old pass or speed is reused.
- Favorite last-good timestamps include the actual valid native-transfer time. Re-import/liking rejects stale, partial and failed transfer rates while preserving explicitly historical last-good evidence. Expanded proxy details and the Saved Messages template use the same completed-transfer validity rule.
- Data Saver copy now matches its actual sample/round plan. Full local-data deletion confirmation accurately lists the data it deletes and the Telegram session it preserves.

## Limits and Remaining Risks

- Actual logout and full-data deletion were deliberately not executed against the user's logged-in app. Deletion/data-integrity logic has isolated automated tests; cancellation/confirmation was exercised on-device.
- The existing emulator has Google Play services disabled. Chrome opens for external links but requests Play services, so browser-to-channel completion and an external Telegram application's connection flow are not verified. No system component was enabled or other laptop app changed.
- Stable/Beta controls work, but the owner's signed release endpoint is unconfigured. Live update download/install cannot be honestly marked complete; manifest/hash/signature policy is covered by automated tests.
- No physical phone, cellular operator, other Android API/ABI runtime, full 1800-route completion, sustained large-file throughput, or Baseline Profile/Macrobenchmark performance run was available in this pass.
- Pre-run duration is a heuristic based on expected candidate yield and configured workers. Actual time can be longer with more survivors, adaptive worker reductions, timeouts or user pauses; it is not an upper-bound promise.
- Scheduling controls were exercised; waiting for every 6/12/24/48-hour background schedule was not part of this run.
- Existing Telegram authentication was preserved. Signed-out login/OTP/logout paths were not repeated on the user's account.
- Passing tests do not prove that all possible bugs are absent, or that public proxies will stay online.

# Physical Phone Acceptance Run

Date: 2026-11-03. Status: bounded experimental-release QA. Not a stable, bug-free
or all-device acceptance claim. Public publication receipts are recorded separately.

## Scope And Safety

- Samsung SM-A520F, Android 8.0.0 / API 26, arm64, 1080x1920 / 480 dpi.
- At initial inspection the owner app was version 2.18 / 20. The owner later
  explicitly confirmed personally uninstalling it. No test-tool uninstall or
  clear-data command was issued; no original private database/session was read.
- Install the new build separately as ProxyX QA, package suffix `.audit`.
- Owner authorized using the existing Telegram API configuration locally and
  in publication builds. Gradle reads its configured input without printing
  credential values; source packages still exclude private configuration.
- Owner authorized network test data without a fixed cap. Keep test sizes
  bounded and record actual attempted transfer sizes and observed consumption.
- Owner enters OTP/password directly on the phone. No personal chats are read.
- The audit release build is minified/non-debuggable but Debug-certificate
  signed for isolated testing; it is not the publication signing identity.

## First Observations

- Isolated 8.0.0-rc1 / 77 installed and opened successfully. Diagnostic Debug
  first start was 3915 ms; this is not an optimized-release startup benchmark.
- Seven native migration/JNI/template/key tests passed on API 26 in 0.338 s.
- 361 unit tests / 64 suites passed. The combined build was intentionally
  stopped during slow lint analysis to prioritize the requested phone install.
  Separate APK assembly then succeeded in 1m 36s; lint remains to rerun.
- Background collection obtained 1452 real proxies on the phone's Wi-Fi and
  performed its existing bounded verification. No synthetic proxy rows inserted.
- English/Persian, RTL, light/dark and auto-refresh off were exercised. Language,
  dark theme and disabled auto-refresh survived force-stop/restart.
- A display ambiguity was found: selected-card MTProto latency and row TCP
  latency had no type distinction. RC2 adds explicit metric types and uses the
  current protocol value except in the explicitly TCP-sorted list. Compact gauge
  ticks were moved outside its arc to leave caption space. Render recheck pending.
- The owner was handed phone/OTP/password entry directly on the phone; tests do
  not read or type those credentials. Authenticated acceptance is pending.

## Authenticated Device Evidence

- Owner confirmed login completion. The encrypted session remained ready after
  instrumentation restarted the app and after installing minified RC2 over RC1.
- Eight physical-device native tests passed in 1.092 s, including a reconstructed
  v1-to-v16 Room migration fixture. No owner database was used for that fixture.
- RC2 combined verification succeeded in 10m 05s: 361 unit tests, zero failures,
  release lint zero errors/six warnings, instrumentation APK assembly.
- A 1100-entry queue started with three adaptive workers. It paused at 37,
  resumed to 39 and was cancelled intentionally. This is NOT a completed test of
  all 1100 entries. The All control selected all 1452 available entries.
- Full eight-entry pipeline summary: stages 1/2/3 attempted 8 each; seven passed
  stability. All seven received the native file-transfer phase: three successful,
  four unsuccessful, zero unexecuted. Public relay failures are expected network
  results, not counted as successful proxy tests.
- Successful details showed three real rounds and observed ranges. One example:
  download 1.39 MiB/s (1.22-1.56), upload 215 KiB/s (178-252), 8.5 MiB payload.
- Favorite action returned native Saved Messages send success and a local row.
  No personal Telegram chats were opened to inspect receipt. This is send-ACK
  evidence, not independent Desktop receipt evidence.
- Active file testing survived Home/background navigation and landscape/portrait
  rotation. The landscape navigation rail fitted all four destinations.
- Search returned an honest empty result, clearing restored 1452, and verified
  filtering returned eight at that point. All seven sort-menu options plus the
  separate download/upload segments were exercised; unit/Room contracts cover
  ranking policy, while UI observation alone is not an exhaustive pool-order proof.
- WEB feeds were unreachable on this phone network. Seven public bootstrap
  links stayed explicitly unverified. A relay entered stage 2 then timed out;
  no WEB protocol/transfer success is claimed.

## Fixes From Physical Inspection

- RC2 distinguishes MTProto from TCP latency, and gives compact gauge labels
  enough room. Real phone captures confirm both changes.
- RC3 preserves sub-one-percent overall progress instead of truncating active
  work to 0%, names that number Overall, and labels the optional transfer switch
  for accessibility. Animated progress is read by the draw callback; the numeric
  label uses actual runtime progress instead of invalidating composition on
  every animation frame. Two regression tests cover this formatter.
- The local QA helper now also checks hierarchy package ownership: Samsung's
  system chooser can share the caller's window owner. Sharing targets are not
  app evidence; future external handoffs are checked using focus metadata only.

## Performance And Remaining Gates

- RC3 optimized cold-start diagnostics: 1648, 1595 and 1742 ms, median 1648 ms.
  These are am-start timing observations, not Macrobenchmark results.
- An initial UI-automation-assisted scroll run reported 161/446 janky frames
  (36.10%). A less intrusive ten-swipe run without UI dumps during gestures
  still reported 124/581 (21.34%), P50 12 ms / P90 22 ms / P95 26 ms / P99 40 ms.
  This remains an explicit performance limitation; it is not blamed away as
  laptop memory pressure. The physical phone's supported display rate is 59 Hz.
- Process PSS after that run was approximately 95 MiB. App-specific crash/ANR
  event collection returned zero matching events at the RC4 smoke checkpoint.
  Absence in the available event buffer is not an all-time crash-free guarantee.
- Independent RC3 visual verdict: fix. Six of eight prior corrections resolved;
  scaled-gauge geometry and fresh-private visual evidence remained open. RC5
  moves large-font compact labels outside a 96dp face; actual release recapture
  confirms separate labels and a complete Start action. Fresh-private evidence
  is also captured on the production build.
- Full import/export persistence round-trip, positive destructive operations,
  generic-proxy end-to-end testing, cellular network transition and complete
  1100-entry execution remain unaccepted. The WEB provider attempted timed out.
- API 33+ permission UX, modern foreground-service behavior, foldables/tablets,
  runtime 16 KiB compatibility and formal Baseline Profile/Macrobenchmark gates
  are not established by this API 26 phone. The earlier emulator ANR is not
  resolved by assumption. Static 64-bit ELF segment and APK alignment checks
  passed, which is narrower evidence.
